SETUP GUIDE

Host Mira for your group.
One file, five settings, one command.

Mira runs on a computer or server you look after. Your friends never see any of this: they just get a link.

  • Ready-made Docker image
  • Sign in with a password you choose
  • Photos stay on your own disk
  • Open source, MIT licence
Start the setup  ↓

What you’ll need

A machine with Docker

Any computer or server with Docker and Docker Compose. Nothing to build: Mira comes as a ready image.

An address for your friends

A domain name and an HTTPS reverse proxy (Caddy, Traefik, nginx or a tunnel) pointing at Mira. Trying it on your own computer first? Skip this.

Room for the photos

Disk space for photos and videos (original videos are large), and a plan for backing them up.

No app to register with Google or GitHub: you sign in with a password you choose. Sign-in services can be added later for friends who should create their own albums.

Three steps. That’s the whole setup.

  1. 1

    Save the Compose file

    Make an empty folder and save this as compose.yaml in it. It is the same file as deploy/compose.prod.yaml in the repository and is attached to every release.

    compose.yaml
    Show the file (about 60 lines) 
    # Mira, one server. Save this file as compose.yaml in an empty folder, put a .env file
# beside it (see the hosting guide), then run:  docker compose up -d
# From a clone of the repository instead:
#   docker compose --env-file .env -f deploy/compose.prod.yaml up -d
# Guide: https://github.com/Humalio/mira/blob/main/docs/DEPLOYMENT.md
services:
  db:
    image: postgres:18-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-mira}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB:-mira}
      PGDATA: /var/lib/postgresql/data/pgdata
    volumes:
      - mira_pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ['CMD-SHELL', 'pg_isready -U ${POSTGRES_USER:-mira} -d ${POSTGRES_DB:-mira}']
      interval: 5s
      timeout: 3s
      retries: 10
  mira:
    # The release to run. Pin a version; there is no "latest" tag.
    image: ${MIRA_IMAGE:-ghcr.io/humalio/mira:0.1.0}
    restart: unless-stopped
    stop_grace_period: 120s
    environment:
      # The exact address people type, scheme included, e.g. https://photos.example.org
      ORIGIN: ${ORIGIN:?set ORIGIN}
      PUBLIC_ORIGIN: ${PUBLIC_ORIGIN:-${ORIGIN}}
      DATABASE_URL: postgres://${POSTGRES_USER:-mira}:${POSTGRES_PASSWORD:?}@db:5432/${POSTGRES_DB:-mira}
      MEDIA_DIR: /data/media
      BODY_SIZE_LIMIT: ${BODY_SIZE_LIMIT:-64M}
      ADDRESS_HEADER: ${ADDRESS_HEADER:-X-Forwarded-For}
      XFF_DEPTH: ${XFF_DEPTH:-1}
      SHUTDOWN_TIMEOUT: ${SHUTDOWN_TIMEOUT:-30}
      AUTH_SECRET: ${AUTH_SECRET:?set a 32+ character AUTH_SECRET}
      # Who is in charge. Either a password of 12+ characters for the sign-in page...
      MIRA_ADMIN_PASSWORD: ${MIRA_ADMIN_PASSWORD:-}
      MIRA_ADMIN_NAME: ${MIRA_ADMIN_NAME:-}
      # ...or exact accounts at a sign-in service below, such as github:123456.
      MIRA_ADMIN_IDENTITIES: ${MIRA_ADMIN_IDENTITIES:-}
      # Who runs this copy and how long photos are kept, shown to guests. Optional.
      MIRA_OPERATOR_NAME: ${MIRA_OPERATOR_NAME:-}
      MIRA_OPERATOR_CONTACT: ${MIRA_OPERATOR_CONTACT:-}
      MIRA_RETENTION_NOTE: ${MIRA_RETENTION_NOTE:-}
      # Optional sign-in services for album owners; each needs both values.
      AUTH_GOOGLE_ID: ${AUTH_GOOGLE_ID:-}
      AUTH_GOOGLE_SECRET: ${AUTH_GOOGLE_SECRET:-}
      AUTH_FACEBOOK_ID: ${AUTH_FACEBOOK_ID:-}
      AUTH_FACEBOOK_SECRET: ${AUTH_FACEBOOK_SECRET:-}
      AUTH_GITHUB_ID: ${AUTH_GITHUB_ID:-}
      AUTH_GITHUB_SECRET: ${AUTH_GITHUB_SECRET:-}
    volumes:
      - mira_media:/data
    ports:
      # Reachable from this machine only; your HTTPS proxy forwards to it.
      - '127.0.0.1:${MIRA_PORT:-5180}:3000'
    depends_on:
      db:
        condition: service_healthy
volumes:
  mira_pgdata:
  mira_media:
  2. 2

    Write five settings

    Save this beside it as .env, with your own values.

    .env 
    # The exact address people will type, scheme included.
ORIGIN=https://photos.example.org

# Two long random values. Make each with:  openssl rand -hex 32
POSTGRES_PASSWORD=
AUTH_SECRET=

# Your sign-in password: at least 12 characters. Use a long one you do not use elsewhere.
MIRA_ADMIN_PASSWORD=

# Shown to guests, so they know whose server their photos go to. Optional.
MIRA_OPERATOR_NAME=Ana Etxeberria
  3. 3

    Start it

    The database is set up on the first start. Point your HTTPS proxy at 127.0.0.1:5180, open your address, and sign in with your password. Your proxy must also pass on each visitor’s address in an X-Forwarded-For header. Caddy and Traefik send it by themselves; nginx needs one line, shown in the deployment guide. Without it, Mira cannot tell your guests apart, and they all share one set of request limits.

    Terminal 
    docker compose up -d

Mira 0.1.0 is the first release and installs into a fresh database; there is no automatic upgrade from earlier development builds. Until its image appears on the releases page, build it from the source as the deployment guide describes. The guide also covers proxies, backups, limits and updating.

The settings, in plain words

ORIGIN
The address in the browser’s address bar, exactly: https://photos.example.org, with no path and no slash at the end. Joining and signing in from any other host name or port are refused, so a mismatch here is the usual reason “nothing happens” when a form is sent. To try Mira on the same computer, use http://localhost:5180.
MIRA_ADMIN_PASSWORD
The password for the sign-in page. Whoever knows it is the administrator. After ten wrong tries the password sign-in pauses for five minutes. Changing it signs that account out everywhere.
PUBLIC_ORIGIN
The address written into invitation links and QR codes. Leave it out and it is the same as ORIGIN, which is right for almost everyone.
MIRA_IMAGE
Which release to run. Leave it out to run the version named in the Compose file, or pin another, such as ghcr.io/humalio/mira:0.1.0, from the releases page. There is no “latest” tag: you choose when to update.
MIRA_PORT
The port Mira listens on, on this machine only (127.0.0.1). The default is 5180. Your HTTPS proxy forwards to it; it is deliberately not reachable from the network directly.

Once it’s running

Make the first album

Create an album and share its link or QR code with your group; there is a printable QR card for the table. Guests join in their browser by typing a name.

Nobody but you can create albums until you say so: a new copy of Mira starts with registration closed.

Stay in charge of who’s in

Invitation links can be forwarded, and anyone who has one can join that album. You can review uploads before the group sees them, close an album when the event is over, and replace a link that has travelled too far.

Let friends own albums

The password is one account: yours. For friends who should create their own albums, register Mira with Google or GitHub (the callback address is https://your-domain/auth/callback/google or .../github), put the two values in .env, and choose who may register under Admin, Settings. 

AUTH_GOOGLE_ID=your-client-id
AUTH_GOOGLE_SECRET=your-client-secret

Keep it cared for

Back up the database and the media volume, together. Keep your server and Mira up to date, watch the free disk space, and set upload and storage limits in the admin settings.

Self-hosting gives you control over the home for your albums. It also makes you responsible for keeping it running, and for the photos people put in it.
